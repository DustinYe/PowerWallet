屏幕组合覆盖 800×600 至 3840×2160，缩放 100%、125%、150%、200%、250%、300%。这是渲染及布局模拟，实际电脑另外检查了 250% 缩放；未宣称逐个更改电脑分辨率或使用了所有规格的实体显示器。

自动检查覆盖：

- 设备输出解析，包括 ADB 启动信息、未授权和离线。
- 未适配的固件、机型、缺少 Google 钱包、连接授权变化时，在修改手机前拒绝激活。
- USB 安装失败时不传输或启动助手，并显示可操作的提示。
- 正常激活流程的顺序，以及启动后必须收到实时助手状态。
- 更新固件后仍允许基于原设置备份恢复。
- Windows 端不猜测或硬编码恢复为小米钱包。
- 日志隐藏设备序列号和 Windows 用户目录。
- 内置文件存在；每组布局的窗口尺寸、操作按钮和横向溢出。

README 中的截图来自离线布局测试，使用模拟连接状态，不包含真实设备序列号、支付卡或账户信息。

## 已有 Android 真机验证

在同一台小米 13 Ultra、同一国行系统上：

- 1.0.0：用户确认实体双击可打开 Google 钱包卡片页面；拔线、锁屏后都可使用。
- 1.0.0：手机插件的状态与停用恢复按钮已验证，恢复到原来的 `mi_pay`，随后重新激活。
- 1.0.1：用户确认人脸识别成功、尚未上滑的锁屏状态也能打开钱包。日志记录两次从“锁屏仍显示、设备已验证”变为“锁屏已退出”，系统前台为 Google 钱包卡片页面。
- 1.0.2：保留上述按键识别与钱包启动逻辑，新增供电脑端使用的 `--status` 和 `--restore` 控制命令。9 组按键识别测试与 APK 签名校验通过。新增命令尚未在真机复测。

本次未进行真实 NFC 读卡器付款交易，也未验证手机重启后的自动恢复。当前设计明确要求重启后通过电脑重新激活。
